## 分段脚本

### S1 · 0:00–0:15（15 秒）

- **画面**：`slides/s1.png` 封面
- **口播**（约 60 字）：
  > 这是我们的参赛作品：AI 开票 Agent 版本评测器，版本 v0.3.0。它要回答的不是 Agent 会不会开票，而是——两个版本的执行轨迹，哪一个更值得上线。

### S2 · 0:15–0:40（25 秒）

- **画面**：`slides/s2.png` 问题页
- **口播**（约 100 字）：
  > 先说问题。如果只看成功率，一个 Agent 没完成任务，可能是两件完全不同的事：一种是它在向用户追问补充信息，任务没完成，但这是正确行为；另一种是金额算错了，却真的把发票开了出去。两种都叫没成功，后果却差一个量级。所以我们的结论不是一个数，而是一组可验证的事实。

### S3 · 0:40–1:05（25 秒）

- **画面**：`slides/s3.png` 架构图
- **口播**（约 100 字）：
  > 架构上分两层。内层是确定性规则：金额口径与计算、确认前置、重复风险、合法流程转移、工具结果与回调，全部由代码判定，同一输入永远同一结果。外层是可选的大模型独立审计：它只读原始轨迹，不读我们的评测结果，输出还要过一遍契约校验。正式评分只由内层产生——关掉模型，输出完全不变。

### S4 · 1:05–2:00（55 秒）★核心

- **画面**：WebUI `#case=INV-V07&tab=summary`，然后切 `timeline`
- **操作动作**：
  1. 停在 `summary`（2 秒）→ 口播到"左边是证据链"时
  2. 点 **A/B 时间线** 标签 → 滚到 B-05 / B-08 / B-09 / B-10
  3. 口播到"右边是分数口径"时 → 指向右侧 Rubric 卡（`70 分 → 20 分`）
- **口播**（约 200 字）：
  > 这是验证集里的一个例子，INV-V07。左边是证据链：B-05 采集金额时，应该是一千元不含税、六十元税额、一千零六十元含税，实际算成了一千、六十六、一千零六十六。这个错误一路传播：B-08 提交、B-09 回调成功、B-10 生成发票。首错是 B-05。右边是分数口径的差别：旧的固定扣分账本给七十分，因为它只按根因标签扣一次分；而影响感知的 Rubric 会问一句——错误金额是不是真的开出去了？是，于是封顶二十分。这里差的五十分，就是「只算错」和「真开票」的差别。

### S5 · 2:00–2:40（40 秒）

- **画面**：WebUI `#case=INV-V08&tab=summary`，切 `timeline` 看 A-07 / A-08
- **操作动作**：停在 summary 说"确认预览"→ 切 timeline 指向 A-07 的 3710 与 A-08 的 3711
- **口播**（约 140 字）：
  > 第二个例子，INV-V08。A 版本在确认预览时给出的是含税三千七百一十元，用户的确认也是基于这个值；但提交时实际传出去的是三千七百一十一元。预览和提交不一致，首错是 A-08，也就是提交这一步。这类错误在只看成功率的报表里看不出来，因为最终发票确实开出来了。

### S6 · 2:40–3:10（30 秒）

- **画面**：WebUI `#case=INV-V04&tab=sources`（四方对照）
- **操作动作**：指向 local_llm 一栏的"缺失/契约拒绝"状态
- **口播**（约 110 字）：
  > 我们同时跑了四个源：确定性评测、人工复核、本地模型、云端模型。这里展示的是四源对照，注意两件事：第一，我们不做多数投票；第二，本地小模型在 INV-V04 上输出了非法结论，被程序契约拒绝——我们把它作为事实保留，而不是丢掉。

### S7 · 3:10–3:40（30 秒）★交付物导览

- **画面**：文件资源管理器打开 `outputs/submission-package-v0.3.0/`，再打开 `VERIFY-REPORT.md` 预览
- **操作动作**：先让 7 个文件同屏（高亮 `validation-submission.jsonl`、源码 zip、`SHA256SUMS`），再切 VERIFY-REPORT 前 10 行
- **口播**（约 110 字）：
  > 这是官方七节的版本报告，每一条结论都带证据事件编号。旁边是提交物：结果 JSONL、自包含的源码包、五阶段验证报告、以及校验和清单。评审拿到这个包，可以直接复跑。

### S8 · 3:40–4:00（20 秒）

- **画面**：终端执行 `python scripts/verify.py --with-rubric`（**可现场跑，约 15–20 秒；也可贴预跑结果**）
- **操作动作**：命令跑完，高亮 `结论：全部通过（5/5 阶段）` 与 `128 passed`
- **口播**（约 75 字）：
  > 验证部分：一百二十八个测试、训练集二十八个 run、验证集十六个 run；官方格式校验通过；同一输入跑两次，输出逐字节相同。

### S9 · 4:00–4:20（20 秒）

- **画面**：`slides/s6.png` 边界与后续
- **口播**（约 80 字）：
  > 最后是边界。验证集没有官方逐 run 标签，人工复核是我们的独立判断；跨领域的规则层仍然耦合；反事实归因目前只有设计。我们把这些写清楚，因为不把能力边界说大，本身也是可复现的一部分。

## 念稿节奏提示

- 每段开头留 **0.3–0.5 秒**空白，方便剪辑对齐；
- 数字（七十、二十、一千零六十）**放慢半拍**，这是评审最想听清的部分；
- 全程不出现"我们很厉害/显著提升"这类词——用事实和数字说话。

## 如果要 TTS 配音

本机 `edge-tts` 可用，示例：

```bash
edge-tts --voice zh-CN-YunxiNeural --text "……" --write-media s1.mp3
```

建议：**优先真人**（可信度更高）；TTS 作为兜底，选 `zh-CN-YunxiNeural`（男声）或 `zh-CN-XiaoxiaoNeural`（女声），语速 `--rate=-5%`。

# 竖屏短视频版（60–75 秒 · 抖音 / 视频号 / 小红书 / B站竖屏）

> 从 4:20 正片里裁出的"一条能独立传播"的版本。
> 逻辑：**钩子 3 秒 → 一个反直觉结论 → 一个真案例 → 一个可复现动作 → 收束**。
> 不需要真人出镜；用正片的 PPT 页 + WebUI 录屏 + 大字幕即可。

## 画面规格

| 项 | 设置 |
|---|---|
| 画幅 | **1080 × 1920（9:16 竖屏）** |
| 安全区 | 上下各留 15%，左右各留 8%（避开平台 UI 与字幕） |
| 字幕 | **大号**，每行 ≤ 12 字，底部 1/4 处；关键词加色（如 `70分` `20分` `开了错票`） |
| 节奏 | 每 3–5 秒切一次画面，别让一屏停太久 |
| 素材 | `slides/s1–s6.png` + WebUI 录屏（V07 时间线 / Rubric 卡）+ 终端命令 |

## 分镜与逐字稿（60 秒版）

### 0:00–0:03 · 钩子

- **画面**：黑底大字 →「两个 AI，都失败了」→ 下一帧「一个该表扬，一个该报警」
- **口播**：
  > 两个 AI 都失败了。一个该表扬，一个该报警。

### 0:03–0:12 · 反直觉结论

- **画面**：`slides/s2.png`（两张卡：正确等待 / 错误开票）
- **口播**（约 40 字）：
  > 因为「成功率」这个数，会把"追问用户补充信息"和"金额算错却真把发票开出去"算成同一件事。

### 0:12–0:30 · 真案例（核心证据）

- **画面**：WebUI `#case=INV-V07&tab=timeline` —— 指向 `B-05`，再拉到 `B-10`
- **口播**（约 80 字）：
  > 看这一条轨迹。B-05 采集金额：该是一千零六，实际算成一千零六十六。错误一路传下去——B-08 提交、B-09 回调成功、B-10 生成发票。真发票，真的开出去了。

### 0:30–0:42 · 分数差在哪

- **画面**：`slides/s4.png` 右侧（`70 分` → `20 分`），或 WebUI 的 Rubric 卡
- **口播**（约 50 字）：
  > 旧口径给七十分，因为它只按根因扣一次分。加上"影响封顶"之后是二十分——错误发票真开了出去，这个后果该被看见。

### 0:42–0:52 · 可复现动作

- **画面**：终端执行 `python -m pytest -q` 与 `python scripts/verify.py --with-rubric`，高亮 `全部通过（5/5 阶段）`
- **口播**（约 40 字）：
  > 这些结论不是我说的，是能复跑的：一百二十八个测试、五阶段回归，同一条命令你也能看到。

### 0:52–1:00 · 收束

- **画面**：`slides/s1.png` 封面（项目名 + `v0.3.0`）
- **口播**（约 35 字）：
  > 别只报成功率。让每个分数都能回指到：哪个事件、哪个字段、什么后果。

## 剪辑清单（照做即可）

1. 用正片的 1080p 录屏，**裁成 9:16**（裁中间，保证 WebUI 关键行不被切）；
2. 竖屏时 WebUI 会显窄——**优先用 PPT 页做讲解**，WebUI 只切"时间线"和"Rubric 卡"两处特写；
3. 字幕逐句打，**数字单独放大**（`1060` / `1066` / `70` / `20`）；
4. 背景音乐选无版权轻鼓点（BPM 100–120），音量压到人声 20%；
5. 结尾 2 秒留白 + 账号名/项目名，不要喊"点赞关注"。

## 平台差异（同一素材三种发法）

| 平台 | 时长 | 封面 | 标题方向 |
|---|---|---|---|
| 抖音 | 60s | 大字「70 分 vs 20 分」 | 反直觉结论型 |
| 视频号 | 60–90s | 封面用 s4（分数对照） | 工程/职场干货型 |
| 小红书 | 图文（6 页图 + 1 段文字） | s1 封面 | 清单/避坑型：<br>「评测 Agent 别只看成功率：4 个可验证事实」 |
| B站 | 4:20 正片 | s1 | 完整版投稿 |

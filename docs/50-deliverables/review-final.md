## 三、本轮审查闭环

1. **题内目标缺失**：不再把缺少 `invoice_should_exist` / `acceptable_snapshot_state` 当作默认匹配，降级为 `INSUFFICIENT_EVIDENCE`。
2. **金额编造**：题内未提供金额而 Agent 填入数值时，归因 `FIELD_FABRICATION`。
3. **口径自拟**：题内未提供含税/不含税口径时，只有明确请求 `amount_basis` 才算追问；其他字段补充请求不能替代。
4. **重复归因**：同一 `(label, first_fault_event_id)` 合并解释与证据，只扣一次。
5. **流程边界**：新增缺必经中间步和合法截短前缀测试。
6. **依赖说明与 CI**：README 补齐运行环境；GitHub Actions 执行测试。
7. **ADR-003**：本版不接入 LLM。
8. **ADR-004**：已发现真实归因缺口，但只采用定性依赖链，不实现完整反事实引擎。
9. **可选 LLM 盲审**：新增独立 `audit`/`compare-audit`，不进入正式评分；已用本地
   `deepseek-r1:8b` 完成 `INV-V03` 试点，模型错误会被契约校验拦截。
10. **run 级证据完整性**：错误运行在最小根因链之外补充回调和终态；正确完整流程覆盖采集、校验、预览、提交、回调和终态，避免只用最后两个事件证明成功。
11. **LLM 盲审契约**：当前 Prompt 为 `llm-audit-v5`；成功 run 仍必须提供非空证据，有根因的运行不得标记为成功，非法候选结果会被程序拒绝。
12. **四源对照报告**：确定性、人工、本地 LLM、云端 LLM 分别统计方向、根因、首错和证据差异；本地 V04 契约拒绝被保留为事实，不静默补造。
13. **LLM 分析附录**：可选分析层只能输出事实、推断和未知，事件锚点与置信度由程序校验；正式报告和结论不受模型影响。

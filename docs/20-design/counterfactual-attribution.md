# 反事实修复与对象感知信用分配（候选）

> 状态：**设计与边界可继续完善，代码不进入基础 MVP**。进入实现的门槛见 [`decisions.md`](decisions.md) ADR-004：先完成 T-010 训练集回归，并观察到至少两个真实的归因缺失或重复。

> 评分接入候选：[证据约束与影响感知 Rubric](evidence-impact-rubric.md)。反事实分析只决定传播、独立性和责任边界，不直接修改正式布尔值或 `quality_score`。

## 动机

仅按 `seq` 找“最早异常事件”容易把时间先后误当成因果，也难以回答：

- 哪些事件是首因，哪些只是复制了错误结果；
- 多个独立根因为什么可以同时存在；
- 工具正确拦截、用户输入和外部服务结果应归功或归责给谁；
- 一个 Case 的版本差异究竟来自哪项行为变化。

本候选把赛题要求的“首因 + 传播链”扩展为一种**证据约束的最小修复分析**，并在此基础上做对象感知的信用分配。

依赖图、可修复字段和降级边界的候选细化见 [`counterfactual-dependency-graph.md`](counterfactual-dependency-graph.md)。

## 主要用途

| 用途 | 回答的问题 | 输出 |
|---|---|---|
| 首因与传播 | 修复首因后哪些 finding 消失？ | `removed_findings` / `propagated_event_ids` |
| 根因独立性 | 修复后哪些 finding 仍存在？ | `surviving_findings` |
| 信用分配 | 错误应由 Agent、模型、Harness、工具、用户还是外部服务承担？ | `actor` / `component` / `UNKNOWN` |
| 修复优先级 | 哪个首因消除的下游影响最多？ | 内部排序，不生成精确贡献百分比 |

“模型”和“Harness”无法从单条轨迹可靠区分时，必须输出 `MODEL_OR_HARNESS_UNKNOWN`，不得根据最终答案倒推隐藏原因。

## 核心想法

1. 从事件字段、工具参数、`request_id` 和明确状态转移中提取确定性依赖关系。
2. 按同一 run 的 `seq` 找到候选首因。
3. 只修复首因中的错误字段，并按已知业务规则重算可确定的下游字段。
4. 随修复消失的异常记为传播结果；仍然存在的异常检查是否为独立根因。
5. 将信用对象区分为 Agent、工具/规则服务、用户和外部服务。
6. 最终输出仍只引用实际 run 中真实存在的 `event_id`；反事实结果不能冒充真实轨迹。

## 示例

`INV-T01-B`：

- 修复 `B-05` 的 `amount_basis` 后，`B-07` 预览和 `B-08` 提交中的错误金额属于传播。
- 修复金额不会消除 `B-08` 的 `user_confirmed=false`，因此确认绕过是独立根因。
- `invoice.submit` 正确拒绝未确认请求，信用属于保护机制，不归责为 Agent 的工具故障。

## 允许使用

- 金额口径和金额三元组的确定性重算；
- 购方、商品、`line_items`、原票引用等字段的数据依赖；
- `request_id` 串联提交与回调；
- 规则明确规定的状态转移；
- 将结果作为内部归因依据，并写进现有的根因、影响说明和改进建议。

## 禁止使用

- 假装重新运行 Agent，或让 LLM 想象“另一个版本会发生什么”；
- 推测模拟开票接口未实际返回的结果；
- 生成或替换真实 `event_id`；
- 在只有一条观测轨迹时编造精确贡献百分比；
- 绕过确定性规则，直接修改布尔结论或 `quality_score`；
- 用一个 Case 的信用分配结果推导整体版本结论。

## 可能形成的差异点

- 首因与传播链区分；
- 多个独立根因并存；
- Agent 错误与工具保护性拦截分开归因；
- 对正确等待、正确阻断等行为给予正向信用；
- 在报告中解释修复哪一处最可能消除下游影响；
- 对无法可靠分配的部分明确输出证据不足。

## 试点前置条件

- 确定性评测基线已通过训练集回归；
- 已确认普通“最早异常”规则在真实 Case 上存在漏判或重复归因；
- 试点只作用于内部归因，不改变提交 schema；
- 用 `INV-T01`、`INV-T05`、`INV-T10`、`INV-T14` 对比普通时序归因与最小修复归因，证明新增方法确实改善判断。

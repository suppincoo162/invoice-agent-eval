# docs 导航

本目录是 `invoice-agent-eval` 的**唯一文档入口**。每层只回答一个问题，按编号顺序读。

## 阅读顺序

| 层 | 回答的问题 | 什么时候读 |
|---|---|---|
| [`00-brief/`](00-brief/) | 这是**什么**赛题？数据长什么样？有哪些陷阱？ | 新人加入、忘了细节时 |
| [`10-spec/`](10-spec/) | 我们要**做什么**？怎么算做对了？ | 写代码前 |
| [`05-conventions/`](05-conventions/) | 我们**按什么规矩做事**？踩到哪类场景看哪条？ | **每次动笔/动工前**，按需取对应原则 |
| [`20-design/`](20-design/) | 具体**怎么做**？为什么这么选？ | 设计评审、改架构前 |
| [`30-tdd/`](30-tdd/) | **怎么验证**做对了？哪些该确定性判、哪些该模型判？ | 写测试、改评分口径前 |
| [`40-plan/`](40-plan/) | **谁做、什么时候做**？ | 每次开工前 |
| [`50-deliverables/`](50-deliverables/) | 比赛要**交什么**？ | 冲刺阶段 |

## 六个文件的定位

- **本文件**：导航，只有目录和判据，不写正文
- **`00-brief/`**：赛题与数据的**事实层**。只写「资料说什么」，不写「我们打算怎么做」
- **`10-spec/`**：需求与契约的**规范层**。是"做对"的定义源；与代码冲突时以本层为准
- **`05-conventions/`**：做事规矩的**原则层**。从长期工作区提纯、按本项目适配的六条工程原则 + 两条协作约定。**与 `AGENTS.md` 分工：AGENTS.md 是入口（少而硬），本层是展开（为什么这么定）**
- **`20-design/`**：实现与取舍的**方案层**。含决策记录（ADR），写清"为什么不是另一个选项"
- **`30-tdd/`**：验证的**策略层**。核心是把"确定性校验"和"模型判断"的边界画出来
- **`40-plan/`**：执行的**排期层**。任务可勾选，每项带验收标准
- **`50-deliverables/`**：对外**交付层**。对齐比赛要求的方法说明与版本评估报告

## 备料（外部资料，**未进方案**）

外部技术现状的采集记录，只写"资料说什么"，**不含决策**；要不要用、用在哪，须在 `10-spec`/`20-design` 落笔时才成立。

- [`00-brief/research/jev-decision-models.md`](00-brief/research/jev-decision-models.md) — 判定式模型（Jev）现状、与本题 schema 的结构对照、可借鉴的设计点（2026-10-31 采集）

## 一条硬规矩

**事实进 `00-brief/`，需求进 `10-spec/`，方案进 `20-design/`，验证进 `30-tdd/`，规矩进 `05-conventions/`。**
同一件事不要在两处写正文——需要时用链接指过去。理由：四层会同时演进，写两遍必然漂移。

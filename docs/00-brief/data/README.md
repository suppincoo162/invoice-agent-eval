# AI 开票 Agent 离线轨迹评测初赛学生资料包

本资料包供参赛团队开发和调试 AI 开票 Agent 的离线评测系统。参赛对象是**评测程序**，不是开票 Agent；无需连接云帐房生产系统，也不提供可调用的开票接口。

## 文件清单

| 文件 | 用途 |
|---|---|
| `AI开票Agent离线轨迹评测初赛学生手册.pdf` | 正式学生手册，适合直接分发与阅读 |
| `AI开票Agent离线轨迹评测初赛学生手册.docx` / `.md` | 与 PDF 同内容的可编辑版本 |
| `01_竞赛版流程字典.json` | 15 个流程步骤、状态与结果码的竞赛版定义 |
| `02_公开训练轨迹.jsonl` | 14 个合成 Case、28 条基线/候选版本运行轨迹 |
| `03_公开训练参考标注.jsonl` | 对应训练集的参考判断、根因和证据事件 |
| `04_无标注验证轨迹.jsonl` | 8 个合成 Case、16 条运行轨迹；不提供专家归因标签 |
| `05_提交结果示例.json` | 单 Case 的输出格式示例，采用公开训练 Case |
| `06_提交格式.schema.json` | 每条提交记录的 JSON Schema |
| `07_数据字典与业务规则.md` | 字段释义、状态语义、沙箱业务规则及归因标签 |
| `08_提交格式校验.py` | 本地格式检查工具；只检查结构，不给出正确性得分 |
| `09_模拟客户与商品档案.json` | 全包使用的合成卖方、购方和商品档案汇总；与某Case的上下文冲突时以Case为准 |
| `10_版本评测报告模板.md` | 供团队整理批量指标、Bad Case 证据链与发布建议 |

所有任务、企业、客户、商品、发票编号及工具返回均为合成数据。题目中的税率是沙箱商品配置，不代表现实税务规则。

## 建议使用顺序

1. 阅读学生手册和业务规则。
2. 读取流程字典，理解 `step_id`、`step_status` 和结果码。
3. 用公开训练轨迹与参考标注建立、验证评测方法。
4. 在无标注验证轨迹上生成提交文件，每行一个 Case 的 JSON 对象。
5. 使用格式校验工具检查 Case 覆盖、运行 ID 和证据事件引用。

命令示例：

```bash
python3 08_提交格式校验.py --cases 04_无标注验证轨迹.jsonl --submission your_submission.jsonl
```

本地校验通过只表示文件结构符合要求，不代表评测或归因正确。

## 数据边界

- `reference_result` 是组委会给出的题内业务目标，不是专家对某个 Agent 版本的评分。
- 训练参考标注可用于方法开发；验证集不附专家标签。正式排名所用的隐藏数据由组委会另行管理，不包含在本学生资料包中。
- `WAITING_USER` 可以是正确的阶段性结果；`agent_task_success` 和 `business_invoice_created` 必须分别判断。
- 模拟工具的保护性拒绝不等于工具故障。归因时应定位首个错误事件及其后续传播。
